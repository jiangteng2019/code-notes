# java中的对象类型

简单理解：

1. 前端数据用DTO（如果是简单参数也可以通过@RequestParam注解获取）
2. 返回给前端使用VO （数据路的密码返回不合适，所以还是使用删减字段后对象返回）
3. 数据库实体用pojo （与数据库的表结构一一对应）
4. 业务对象应该为BO（假如关联查询的时候返回来了多个字段，此时没有任何对象能“接”，需要单独定义此类型的“业务对象”）

### 1. **DTO (Data Transfer Object)**
   - **用途**：用于 **前端和后端之间的数据传输**。通常在接收或发送到前端的数据对象中使用。
   - **特点**：简单的数据对象，通常只包含数据字段，不包含复杂的业务逻辑。它主要用于数据的传输，避免了不必要的依赖和复杂性。
   - **例子**：如果前端提交用户注册信息，你可以定义一个 `UserDTO` 来表示前端传来的数据。

### 2. **VO (Value Object)**
   - **用途**：用于 **前端展示层**，特别是在 **UI 层**（如 Web 页面或前端框架）使用的数据对象。VO 对象通常用于封装从后端返回的数据，特别是需要在展示时合并或处理的结果。
   - **特点**：类似于 DTO，但它更专注于用户界面显示所需的数据，可能包含一些特定的视图逻辑，甚至包含一些格式化的方法，帮助将数据转换成展示所需的格式。
   - **例子**：如果你需要在前端展示用户及其订单信息，你可以定义一个 `UserOrderVO`，它包含了 `User` 和 `Order` 的数据，并且可能包含格式化显示的字段。

### 3. **POJO (Plain Old Java Object)**
   - **用途**：用于 **数据库表的实体类**。POJO 是与数据库表一一映射的普通 Java 对象，用于 ORM（如 JPA 或 Hibernate）映射数据库中的记录。
   - **特点**：通常包含数据库表字段的属性，以及 getter、setter 方法。POJO 是与数据库交互的对象，通常没有业务逻辑，仅仅表示数据模型。
   - **例子**：数据库中的 `User` 表可以有一个对应的 `User` POJO 类，它有与表字段对应的属性，如 `id`、`username`、`email` 等。

### 4. **BO (Business Object)**
   - **用途**：用于 **业务层**，封装业务逻辑。BO 是服务层或业务层中的对象，它可以代表业务流程中的一部分数据，通常涉及到多个实体对象的合并、处理和转换。
   - **特点**：BO 对象通常包含更多的业务逻辑和计算。它可能不直接对应数据库中的表，而是根据业务需求将多个 POJO 或 DTO 组合在一起。
   - **例子**：比如，`UserBO` 可以是用于业务操作的对象，包含了用户的基本信息和与用户相关的其他业务数据（如用户的订单、购物车等），可以用来进行业务处理和决策。

---

### 总结：

- **DTO (Data Transfer Object)**：用于前端和后端之间的 **数据传输**。
- **VO (Value Object)**：用于前端展示层的 **视图对象**，专注于展示数据。
- **POJO (Plain Old Java Object)**：用于 **数据库实体类**，表示数据库表的一一映射。
- **BO (Business Object)**：用于 **业务层**，包含业务逻辑的对象，通常是多个数据对象的组合。

这种命名方式在层次分明的架构中非常常见，能够有效区分不同层级的数据对象。通过这种清晰的命名，可以提升代码的可读性、可维护性和一致性。
